# D435i RGB 灯条检测+配对+PnP 系统 - 完全重构版

## 🎯 重构完成

基于您的要求，已完成完整的算法重构：

### ✅ 核心改进

1. **灯条检测+配对** - 不再把单个轮廓当目标，而是两灯条配对
2. **通道差分** - R-G, B-R 处理过曝LED中心

4. **PnP重投影验证** - 重投影误差检查，不盲目信任success
5. **真实D435i内参** - 自动读取RGB真实内参和畸变

## 📋 算法流程

```
RGB图像
    ↓
通道差分检测 (R-G, B-R) + 亮度
    ↓
二值化
    ↓
findContours
    ↓
提取灯条候选 (LightBarCandidate)
    ↓
几何筛选（面积、长宽比、矩形度、方向、亮度）
    ↓
灯条配对算法（长度、角度、距离、对齐度）
    ↓
选择最佳配对 (LightBarPair)
    ↓
从两灯条生成目标四角点 [TL, TR, BR, BL]
    ↓
PnP (solvePnP)
    ↓
重投影误差验证
    ↓
距离合理性检查
    ↓
输出位姿 (X, Y, Z, Roll, Pitch, Yaw)
```

## 🔧 参数调整指南

所有参数在 `core/config.py` 中集中管理。

### 1. 通道差分检测

```python
# 红灯检测：R-G阈值
RED_CHANNEL_DIFF_THRESHOLD = 30  # 降低=检测更多，提高=更严格

# 蓝灯检测：B-R阈值
BLUE_CHANNEL_DIFF_THRESHOLD = 30

# 亮度阈值
BRIGHTNESS_THRESHOLD = 200  # 降低=包含更多区域
```

**调整建议**：
- 如果检测不到灯条，降低阈值
- 如果误检太多，提高阈值

### 2. 灯条候选筛选

```python
# 面积
MIN_LIGHT_BAR_AREA = 50
MAX_LIGHT_BAR_AREA = 10000

# 长宽比（灯条应该很细长）
MIN_LIGHT_BAR_ASPECT_RATIO = 2.0    # 最小长宽比
MAX_LIGHT_BAR_ASPECT_RATIO = 50.0

# 矩形度（接近矩形程度）
MIN_LIGHT_BAR_RECTANGULARITY = 0.5  # 0-1，越大越接近矩形

# 方向约束
EXPECTED_LIGHT_BAR_ANGLE = 90.0     # 期望方向（竖直=90°）
LIGHT_BAR_ANGLE_TOLERANCE = 30.0    # 允许偏差±30°

# 亮度
MIN_LIGHT_BAR_BRIGHTNESS = 150      # 灯条内部平均亮度
```

**调整建议**：
- 长宽比太严格会漏检，太宽松会误检
- 方向约束根据实际灯条方向调整
- 矩形度过滤不规则形状

### 3. 灯条配对参数

```python
# 长度相似度
MAX_LENGTH_DIFF_RATIO = 0.5    # 两灯条长度差异比例

# 角度相似度
MAX_ANGLE_DIFF = 15.0          # 两灯条角度差（度）

# 距离约束
MIN_PAIR_DISTANCE_RATIO = 0.5  # 最小距离/平均灯条长度
MAX_PAIR_DISTANCE_RATIO = 8.0  # 最大距离/平均灯条长度

# 垂直对齐
MAX_VERTICAL_OFFSET_RATIO = 1.0  # 垂直偏移/平均长度

# 配对评分权重
WEIGHT_LENGTH_SIMILARITY = 0.25
WEIGHT_ANGLE_SIMILARITY = 0.25
WEIGHT_DISTANCE = 0.20
WEIGHT_ALIGNMENT = 0.30

# 最小配对得分
MIN_PAIR_SCORE = 0.5  # 提高此值=更严格配对
```

**调整建议**：
- 如果配对失败，降低 `MIN_PAIR_SCORE`
- 如果配对错误，调整各项权重
- 根据实际灯条间距调整距离比例

### 4. PnP验证

```python
# 重投影误差阈值
MAX_REPROJECTION_ERROR = 8.0  # 像素

# 距离合理性
MIN_DISTANCE = 0.05  # 最小距离（米）
MAX_DISTANCE = 10.0  # 最大距离（米）
```

## 🐛 故障诊断

### 问题1：检测不到灯条候选

**终端显示**：`检测到 0 个灯条候选`

**可能原因**：
- 通道差分阈值太高
- 亮度阈值太高

**解决**：
1. 降低 `RED_CHANNEL_DIFF_THRESHOLD`（从30降到20）
2. 降低 `BRIGHTNESS_THRESHOLD`（从200降到150）

---

### 问题2：检测到灯条但全部被过滤

**终端显示**：
```
检测到 5 个灯条候选
筛选后剩余 0 个有效灯条
```

**可能原因**：
- 长宽比不满足
- 矩形度不满足
- 亮度不满足

**解决**：
1. 查看终端输出每个候选的特征
2. 放宽对应的筛选参数

---

### 问题3：灯条配对失败

**终端显示**：`无法找到有效的灯条配对`

**可能原因**：
- 只检测到1个灯条
- 配对得分太低

**解决**：
1. 如果只有1个灯条，检查另一个灯条为何被过滤
2. 降低 `MIN_PAIR_SCORE`（从0.5降到0.3）
3. 打开 `DEBUG_SHOW_PAIRS = True` 查看所有配对尝试

---

### 问题4：PnP重投影误差过大

**终端显示**：`重投影误差过大: 12.5 > 8.0`

**可能原因**：
- 角点位置不准确
- 灯条检测不完整
- 2D-3D对应错误

**解决**：
1. 提高灯条检测精度
2. 检查四角点P1-P4是否正确标注在目标四角
3. 如果角点正确但误差大，可以适当提高 `MAX_REPROJECTION_ERROR`（慎重）

---

### 问题5：检测到错误目标

**窗口显示**：框住了机械零件而不是灯带

**可能原因**：
- 白色/反光区域被误检为灯条
- 配对算法选择了错误的两个轮廓

**解决**：
1. 提高 `MIN_LIGHT_BAR_BRIGHTNESS`（排除暗区域）
2. 提高 `MIN_LIGHT_BAR_RECTANGULARITY`（排除不规则形状）
3. 调整配对参数，确保选择的是真正的灯条

## 🎓 算法理解

### 为什么不直接用单个轮廓？

单个轮廓可能是：
- 灯条的一部分
- 机械零件
- 反光
- 任意长条结构

### 为什么需要配对？

两个灯条组成目标才能：
- 确定目标的完整几何结构
- 准确计算四个角点
- 提供稳定的PnP输入

### 为什么需要重投影验证？

`solvePnP` 返回 `success=True` 不代表结果正确：
- 输入角点可能不准确
- 2D-3D对应可能错误
- 需要通过重投影误差验证真实性
